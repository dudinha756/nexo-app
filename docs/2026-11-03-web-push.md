# NEXO — Push em segundo plano (03/11/2026)

## Arquitetura

- O usuário ativa manualmente as notificações em **Minha vida** (/vida), concede permissão e registra um dispositivo.
- Em iPhone/iPad, o NEXO precisa ser adicionado à **Tela de Início** e aberto pelo ícone, pois o push com o navegador fechado exige um web app de Tela de Início. O site continua acessível normalmente pelo navegador.
- Uma assinatura Web Push criptografada é registrada em nexo_push_subscriptions sob user_id. Desativar remove a assinatura do servidor e do navegador.
- O service worker public/sw.js exibe notificações com a página fechada e abre o NEXO quando o usuário toca nelas. Não intercepta requisições nem implementa cache offline.
- O servidor assina envios com VAPID_PRIVATE_KEY, cuja chave não é exposta ao GitHub nem ao navegador; o VAPID_PUBLIC_KEY é público.
- GitHub Actions .github/workflows/push-reminders.yml aciona /api/push/dispatch a cada cinco minutos aproximadamente, usando token OIDC temporário, sem segredo compartilhado. O endpoint verifica assinatura, audiência, repositório, workflow e branch principal.
- O backend envia lembretes por categoria, fuso horário, recorrência semanal/anual, antecedência (15,30,60 min), datas de dia inteiro e resumo diário configurado.
- nexo_push_deliveries impede repetição de uma notificação para o mesmo dispositivo e evento/dia; limite diário configurável.
- Quando o push está ativo, o lembrete local do site é suprimido para evitar avisos duplicados.
- Endpoint POST /api/push/subscribe action=test permite teste manual em dispositivo autorizado, com intervalo mínimo de 60 segundos.

## Variáveis de ambiente (Vercel Production)

VAPID_PUBLIC_KEY, VAPID_PRIVATE_KEY (encrypted), VAPID_SUBJECT (HTTPS origin).

Chaves devem ser geradas para a própria instalação e nunca commitadas. Rotacionar chaves interrompe assinaturas já registradas até que o usuário as renove.

## Ressalvas operacionais

- Push não garante entrega em horário exato. O GitHub Actions pode atrasar ou pular execuções agendadas; o sistema operacional também pode adiar notificações.
- A funcionalidade não é uma notificação nativa de aplicativo da App Store.
- O servidor só envia mensagens após a ativação explícita do usuário no dispositivo e nos filtros de categoria.
- Notificações de aniversário/dia inteiro começam após 8h no fuso registrado; não inventam horários para os eventos.
- O serviço não é capaz de provar o recebimento final sem um teste no dispositivo real.
- Em caso de falha ao enviar, o servidor permite nova tentativa; erros 404/410 excluem assinaturas expiradas.
- Assinaturas são específicas de cada aparelho; desligar em um aparelho não desliga automaticamente em outros.
- Para notificações no iPhone: iOS 16.4+, Safari > Compartilhar > Adicionar à Tela de Início; depois abrir pelo ícone e clicar Ativar push.

## Procedimento de validação

1. Conferir GitHub Actions CI e build Vercel em verde.
2. Abrir /vida com login, adicionar à tela inicial se iPhone, configurar categorias e clicar em "Ativar push".
3. Clicar "Enviar teste", fechar o NEXO e confirmar que o teste apareceu no aparelho.
4. Cadastrar compromisso a ~30 minutos e aguardar execução agendada; confirmar push de lembrete com o site fechado.
5. Validar desativação, troca de conta e prevenção de duplicidades.

As tabelas já foram aplicadas ao banco Neon existente e a migração correspondente é versionada neste repositório.
